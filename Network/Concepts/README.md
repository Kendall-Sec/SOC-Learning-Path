# Network Traffic Basics

**Type:** 📘 Concept Documentation

## What is Network Traffic Analysis?

Network Traffic Analysis (NTA) is the process of capturing, inspecting, and interpreting data as it moves across a network. It gives SOC analysts visibility into what's actually happening on the wire — which hosts are talking to each other, what protocols they're using, and whether that behavior is normal or malicious.

Where host-based tools (EDR, antivirus) see what happens *on* a machine, network traffic analysis sees what happens *between* machines — making it one of the few detection sources an attacker can't easily disable from an endpoint.

---

## Why is Network Traffic Analysis important?

Most attacks eventually touch the network — beaconing to a C2 server, moving laterally, exfiltrating data, or scanning for other hosts. Analyzing traffic lets analysts:

- Detect command-and-control (C2) beaconing
- Identify lateral movement between internal hosts
- Spot data exfiltration
- Confirm or rule out alerts generated by other tools (SIEM, IDS/IPS)
- Reconstruct an attacker's actions during incident response

Even when malware evades an EDR agent, its network behavior often leaves a trace.

## How Network Traffic is Collected

Traffic has to be captured before it can be analyzed. Common collection points include:

### SPAN / Mirror Ports
A switch is configured to copy traffic from one or more ports to a dedicated monitoring port, where a capture tool listens.

### Network TAPs (Test Access Points)
A physical device inserted inline on a network link that passively duplicates all traffic passing through it, without affecting the link itself.

### Host-Based Capture
Capturing traffic directly on an endpoint (e.g., with `tcpdump` or Wireshark) — useful for isolated analysis but limited to that host's view.

### Cloud / Virtual Traffic Mirroring
Equivalent to a SPAN port, but implemented in cloud environments (e.g., AWS Traffic Mirroring, Azure vTAP) to capture traffic between virtual machines.

Captured traffic is typically saved as a **PCAP (Packet Capture)** file, the standard format read by nearly all traffic analysis tools.

---

## Common Tools

- **Wireshark** – GUI-based deep packet inspection and protocol analysis
- **tcpdump** – Command-line packet capture, common on Linux/Unix systems
- **NetworkMiner** – Passive network forensics; reconstructs files, credentials, and sessions from a PCAP
- **Zeek (Bro)** – Generates high-level, structured logs from raw traffic instead of packet-by-packet detail
- **Suricata / Snort** – Signature and rule-based network IDS/IPS
- **Brim** – GUI front-end for exploring Zeek logs and PCAPs together

## Core Concepts

### Packets vs. Flows
A **packet** is a single unit of data traveling across the network. A **flow** (or session) is a sequence of related packets between the same two endpoints — grouping packets into a flow makes it easier to see the overall conversation rather than individual pieces.

### Protocols
Traffic analysis relies heavily on understanding common protocols (TCP, UDP, DNS, HTTP/HTTPS, ARP, ICMP) to recognize what "normal" looks like and spot deviations.

### Encryption
A growing share of traffic is encrypted (TLS/HTTPS), which limits payload visibility. Analysts increasingly rely on metadata — connection patterns, timing, certificate details, and JA3/JA3S fingerprints — rather than payload content alone.

## Typical Workflow

1. Traffic is captured at a SPAN port, TAP, or host.
2. The capture is saved as a PCAP file (or streamed live).
3. An alert (from a SIEM or IDS) points the analyst toward a specific time window, host, or IP.
4. The analyst opens the capture in a tool like Wireshark and filters down to the relevant traffic.
5. Protocols, endpoints, and payloads are inspected for signs of malicious activity.
6. Findings (IOCs, affected hosts, techniques used) are documented and escalated if confirmed malicious.

## Key Takeaways

- Network Traffic Analysis inspects data in transit, complementing host-based tools like EDR.
- Traffic is captured via SPAN ports, TAPs, host-based tools, or cloud mirroring, and saved as PCAP.
- Wireshark, tcpdump, NetworkMiner, and Zeek are core tools for capturing and analyzing traffic.
- Understanding protocols and normal traffic patterns is essential to spotting anomalies.
- Encryption limits payload visibility, pushing analysts toward metadata-based detection.
